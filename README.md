# رحلتي مع المتحدث الصغير

تطوير للمشروع الأصلي، لا مشروع بديل: خارطة أفقية عربية RTL لبرنامج من **32 حصة أصلية** في عالمين مستقلين:

- **المتحدث الواثق** — الحصص 1–16، مروج ربيعية خضراء.
- **المتحدث المؤثر والمطبق** — الحصص 17–32، تلال ذهبية عند الغروب.

لم تتغيّر عناوين الحصص أو ترتيبها، ولم تتغيّر ملفات ليلى وسامي والأخت الصغيرة. منصتا الوسام والتاج محطتا احتفال، وليستا حصتين إضافيتين.

## التشغيل

يتطلب Node.js **22.12 أو أحدث**؛ بيئة الاختبار تستخدم Node 22.

```bash
npm ci
npm run dev
```

يفتح Vite المنفذ 5173 على `0.0.0.0`، ويقبل مضيف المعاينة. الخطوط والشخصيات محلية ولا تعتمد على CDN.

**بدون متغيرات Supabase** يعمل عرض تجريبي للقراءة فقط: الحصة الأولى متاحة، ويظهر تنبيه «وضع تجريبي». لا إعداد PIN، ولا حساب إداري لأول زائر، ولا اعتماد محلي قابل للتلاعب.

للاتصال بالمشروع المستقل `voies`، انسخ `.env.example` إلى `.env.local` واضبط المفتاح **العام فقط**:

```dotenv
VITE_SUPABASE_URL=https://wjsaqivamucqqwfzvaer.supabase.co
VITE_SUPABASE_ANON_KEY=your_public_publishable_or_anon_key
```

أعد تشغيل Vite بعد تغيير المتغيرات. لا تضع `service_role` أو `sb_secret_…` في أي متغير يبدأ بـ `VITE_`.

## تجربة الخارطة

الهوية اللونية مستمدة من النسخة الأصلية: العشب الأخضر الزاهي وخصلاته والأشجار والزهور الأصلية، مع محطات مكتملة زرقاء ومحطة حالية وزر بدء ذهبيين. الواجهة بيضاء بألوان زرقاء وذهبية، وليست طبقة زيتونية باهتة. يحتفظ العالم الثاني بالتلال الذهبية والغروب، ولا تطبّق أي مرشحات لونية على الشخصيات.

- الخارطة تملأ المساحة بين الرأس والشريط السفلي، بلا تمرير رأسي داخلها.
- البداية في اليمين؛ التقدّم يسارًا على مسار Bézier متصل. تُوسَّط المحطة الحالية بهدوء عند الفتح.
- التصفّح بعجلة الفأرة، السحب، اللمس، سهمَي الحافة أو لوحة المفاتيح. عند تركيز محطة ينقل سهم اليسار التركيز إلى الحصة التالية؛ `Home` للبداية و`End` للنهاية.
- انتقال بين العالمين عبر بوابة، والتقاط ناعم عند بدايتيهما، ومؤشر صغير للمستوى في الأسفل.
- **زر واحد فقط «ابدأ الحصة»** في بطاقة المحطة الحالية؛ الشريط السفلي يحتوي «محطتي» وتبديل المستوى و«المدرّب» فقط. بعد إكمال 32 حصة لا توجد حصة حالية أو زر بدء.
- عناوين المحطات تتناوب فوق المسار وتحته. التفاصيل التعليمية الفردية — الهدف والنشاط والتحدي — داخل شاشة الحصة فقط.
- زينة SVG طبقية بتوزيع ثابت وفحص تصادم مع الطريق والمحطات والبطاقات واللافتات والشخصيات. حركات بطيئة، مع احترام `prefers-reduced-motion`.
- أيقونات SVG موحّدة، 32 أيقونة للحصص، أسماء وصول عربية لحالات المحطات، وتركيز واضح وحبس للتركيز داخل الحوارات.

## الدخول والاعتماد

1. ينشئ مسؤول البرنامج حساب المدرّب خارج واجهة الأطفال؛ يدخل المدرّب ببريده وكلمة مروره.
2. يضيف المدرّب تلميذًا من لوحته، ويظهر رمز دخول عشوائي مرة واحدة. تُحفظ تجزئته فقط في قاعدة البيانات.
3. يدخل الطفل بالرمز. يمكنه قراءة تقدّمه ومراجعة حصصه المفتوحة، **ولا يمكنه الكتابة في جدول التقدّم أو استدعاء اعتماد المدرّب**.
4. يتطلب الاعتماد تأكيدًا، ويستدعي `approve_next_session(student_id)` الذي يعيد فحص الدور والملكية في PostgreSQL ويزيد العدد خطوة واحدة فقط. التراجع يعكس آخر خطوة واحدة.
5. تُرسل التحديثات عبر Realtime، ثم يُعرض فتح القفل وتُضاء المحطة التالية. عند إعادة الاتصال يُجلب التقدّم الموثوق مجددًا.

التقدّم **ليس محفوظًا في localStorage أو sessionStorage**؛ التخزين في المتصفح لجلسة الدخول الخاصة بالتبويب فقط. حتى المدرّب لا يستطيع تعديل العدد مباشرة من REST. حماية الرابط المباشر إضافة لسلامة الواجهة، وليست بديلًا عن RLS.

**الإعداد الفعلي:** [Supabase وحساب المدرّب](docs/supabase.md).

**النشر والأتمتة:** [Vercel وGitHub Actions](docs/deployment.md).

## التحقق

```bash
npm run typecheck
npm test                 # المنهج والهندسة والتصادمات + PostgreSQL RLS + تزامن الدخول
npm run test:security    # اختبارات SQL فقط، على PostgreSQL فعلي داخل PGlite
npm run test:e2e         # مصفوفة الشاشات + التنقل واللمس والدخول والاعتماد وإمكانية الوصول
npm run build            # نسخة الإنتاج في dist/
```

اختبارات المتصفح تستخدم محاكاة على مستوى بروتوكول Supabase، لا منفذًا لتعديل التقدّم في تطبيق الإنتاج. تتضمن 30 وضعية: المقاسات `1920×1080` و`1440×900` و`1366×768` و`1024×768` و`820×1180` و`390×844`، لكل منها الأعداد `0، 7، 16، 20، 32`، مع صور إضافية لاحتفالي 16 و32.

الصور في `artifacts/screenshots/`، وتقرير Playwright في `playwright-report/`، ومخرجات axe في `artifacts/axe-map.json`. هذه المخرجات مستثناة من Git. الاختبارات المقلّدة لا تثبت نجاح الدخول أو Realtime على السحابة؛ راجع [تقرير التحقق](docs/verification.md) للفصل بين ما اختُبر محليًا وما تحقّق على الخدمة الفعلية.

اختبارات المتصفح تستعمل Chromium موزعًا عبر npm على Linux x64. على الأنظمة الأخرى ثبّت متصفح Playwright المعتاد بـ `npx playwright install chromium`.
