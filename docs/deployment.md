## النشر التلقائي: تكامل Vercel مع Git

يستعمل المشروع **التكامل الأصلي**، لا مهمة نشر ثانية في Actions:

```json
{
  "git": { "deploymentEnabled": true },
  "github": { "autoJobCancelation": false }
}
```

`main` هو Production Branch، لذلك ينتج عن دمج PR إليه بناء إنتاج جديد. تُنشأ معاينات لبقية الفروع. تعطيل الإلغاء التلقائي يحافظ على بناء الدفعات بالتسلسل بدل إلغاء بناء سابق عند دفعة أحدث. راجع [توثيق Vercel الرسمي](https://vercel.com/docs/project-configuration/git-configuration).

**دليل فعلي، لا مجرد إعداد ملف:** عند دفع الفرع `arena/0f99bb1a-voies` أنشأ التكامل، دون طلب نشر يدوي، النسخة:

- `dpl_G8yDHYgZXS87LAEctP4LTDas47Gb`.
- `source=git`، `READY`، commit `048d4f67ece02f247f179cbcdab3b9525e2fe8f8`.
- [معاينة الفرع الثابتة](https://voies-git-arena-0f99bb1a-voies-abdo12-dels-projects.vercel.app).

أُنشئت أيضًا معاينة يدوية مستقلة `dpl_95mfuES985ngSrEcHysx8vyUrSoM` ووصلت إلى READY؛ إثبات الأتمتة هو النسخة ذات `source=git` أعلاه، وليس الطلب اليدوي. وجود بعض خيارات أحداث GitHub المعطلة في استجابة المشروع لم يمنع تشغيل التكامل؛ الحكم هنا من نتيجة الدفع الفعلية.

لا يلزم سر `VERCEL_TOKEN` في GitHub لهذا المسار، ولا ينبغي تشغيل job نشر موازية فتنتج نسختان لكل دمج. ملفات GitHub Actions تختبر الجودة فقط، وتُرفق صور القبول وتقاريرها. إذا أردت اشتراط نجاح CI قبل الدمج فاجعله required check في قواعد `main`.

## الحماية وCORS للمعاينات

المعاينات محمية بإعداد Vercel Authentication الحالي. طلب غير مسجّل يُعاد إلى صفحة دخول Vercel؛ لم نلغ هذه الحماية. افتح معاينة الفرع بحساب Vercel المصرح له، أو استعمل المعاينة المحلية التجريبية للعرض.

سر Supabase `JOURNEY_ALLOWED_ORIGINS` يسمح بالأصول الدقيقة الآتية:

```text
https://voies.vercel.app
https://voies-abdo12-dels-projects.vercel.app
https://voies-git-arena-0f99bb1a-voies-abdo12-dels-projects.vercel.app
```

معاينات Vercel الفريدة ذات أسماء مختلفة ليست مسموحة تلقائيًا لدخول الرمز/إنشاء الطفل؛ استعمل رابط الفرع أعلاه أو أضف الأصل الدقيق الموثوق. لا تستخدم `*` أو السماح بجميع نطاقات `vercel.app`. لا يحل CORS محل فحص JWT وملكية التلميذ في الخادم.

## ما لم يحدث بعد

طلب التغيير [#2](https://github.com/Abdo12-del/voies/pull/2) مفتوح؛ لم ندمجه أو ندفع إلى `main`. لذلك **نسخة الإنتاج القديمة لم تستبدل بهذه الخارطة بعد**، ولم نختبر عملية دمج إلى `main` في هذه الجولة. ما ثبت فعليًا هو نجاح بناء المعاينة وتشغيله تلقائيًا من Git، مع ضبط فرع الإنتاج على `main`.

بعد موافقة المسؤول والدمج:

1. راجع Deployment الإنتاج وتأكد من `READY` وSHA الدمج الصحيح.
2. افتح موقع الإنتاج واختبر المدرّب والطفل على حسابين/تبويبين منفصلين.
3. تحقق من وصول اعتماد المدرّب إلى الطفل عبر Realtime ومن رفض طلبات كتابة الطفل/اعتماده.
4. إنشاء حساب المدرّب ليس تلقائيًا عند أول زيارة؛ اتبع [إعداد Supabase](supabase.md).
